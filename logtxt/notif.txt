Key Differences
Feature	Foreground Behavior	Background Behavior
App State	App is open and active.	App is minimized, closed, or in the background.
Automatic Notification	

Does not trigger a system notification; must be handled manually.	

Automatically triggers a system notification if the payload includes notification.

Message Handling	Use onMessage() for real-time processing and UI updates.	Use setBackgroundMessageHandler() to process background messages.
Payload Types	Handles messages with both data and notification keys.	Automatically handles notification messages; data messages require explicit handling.
User Interaction	Direct interaction with app content.	User must tap on the notification to return to the app.

{
  "to": "device_token_here",
  "notification": {
    "title": "New Message",
    "body": "You have received a new message.",
    "click_action": "FLUTTER_NOTIFICATION_CLICK" // Optional
  },
  "data": {
    "extra_data_key": "extra_data_value" // Optional, for additional data
  }
}

Using Channels with FCM:
When you send notifications through FCM, you can specify the channel ID in the notification payload. Here’s an example of a payload:
json
Copy code
{
  "to": "device_token_here",
  "notification": {

    "channel_id": "high_importance_channel_id"
  }
}
